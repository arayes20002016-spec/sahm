# بناء إصدار قابل للمراجعة

## ضغط التنزيل والتعافي

في 0.20، تشترط دورة الضغط إكمال المهام تلقائيًا بعد انقطاع خادم الاختبار ست ثوانٍ، دون أوامر استئناف في تلك المرحلة. راجع [سياسة إعادة الاتصال](NETWORK-RECOVERY.md). شغّل أيضًا `npm run smoke:network-retry -- --source-root` ومسار app.asar النهائي، مع `--result-directory` لمجلد جديد؛ يتحقق هذا الفحص من حالة الانتظار والإيقاف وعدم إعادة فتح نافذة أخفاها المستخدم.

بعد التغليف شغّل `npm run test:stress -- --duration-seconds 1800 --application-root` متبوعًا بمسار resources/app.asar، ثم `--runtime` ومسار SAHM.exe، و`--result-directory` لمجلد أدلة جديد. يوضح [دليل الضغط](DOWNLOAD-STRESS.md) حالات القطع والاستئناف وحدود الذاكرة والقرص. احتفظ بنتيجة الدورة الكاملة وتفاصيل الطلبات والبصمات، وافصل أي استئناف صريح بعد عودة الشبكة عن إعادة محاولة حالة اختبار فاشلة. لا يغلق اختبار العملية أو الأرشيف قبول التثبيت داخل VM.

## فحص نوافذ التنزيل بالتزامن

بعد التغليف شغّل `npm run smoke:packaged-download-windows -- --rounds 3 --parallel 2 --ui-delay-ms 6500`. إذا كانت الحزمة في مسار آخر، أضف `--portable` ومسار مجلد SAHM-win32-x64 المطلق. يمكن تعيين `--result-directory` لمجلد أدلة جديد. يرفض الفحص إعادة استخدام مجلد حالة موجود، ولا يعيد الحالات الفاشلة تلقائيًا.

يحمّل كل عامل شيفرة التطبيق من app.asar النهائي داخل Electron مطابق، وبملف مستخدم وخادم محلي خاصين به. تُرسل مقدمة حقيقية لكل استجابة وتظل بقية البيانات محجوبة حتى يسمح الفحص بإكمالها. لا تُحجب طلبات فحص Range ذات البايت الواحد. ينتظر المشغّل وصول جميع العاملين إلى البيانات الجزئية، ثم يرسل إذن متابعة خاصًا بكل عامل بملف ذري ومعرّف جديد. تأخير 6500 مللي ثانية مقصود لتأخير قراءة الواجهة، وليس لتحديد توقيت انتهاء التنزيل.

يتحقق الفحص من جاهزية زر الإيقاف، ثم يكمل الملف الآخر بينما الأول متوقف، ويطلب استئناف الأول عبر زر الواجهة ويتحقق من طلب Range مطابق للإزاحة المحفوظة، ثم يسمح بإكماله ويفحص البايتات. تُسجّل مرحلة الإخفاق والحالات وطلبات الخادم. تظل المهل القصوى حراسًا ضد التعليق؛ لا تُزاد لإخفاء السباق السابق. شغّل هذا الفحص بالتزامن مع `smoke:packaged-browsers` و`verify:release` عند قبول الحزمة، واحتفظ بنتائجها جميعًا.

## تجهيز المصدر والبناء

يجهّز Electron 44 الملف التنفيذي عند أول استدعاء لواجهته أو تشغيله. يستخدم اختبار المشغّل require('electron') للحصول على المسار بعد التجهيز بدل افتراض وجود node_modules/electron/dist مباشرة بعد npm ci. يحتاج التجهيز الأول إلى الشبكة أو ذاكرة تنزيل موثوقة، وتُراجع بصمات Electron بواسطة أداة التنزيل. لا يُلغى الاختبار إذا غاب الملف التنفيذي.

1. ابدأ من مجلد مصدر جديد، وثبّت Node.js 24 وGit for Windows. شغّل npm ci ثم npm audit --audit-level=moderate وnpm run check.
2. شغّل npm run media:setup وnpm run media:verify. لا تغيّر ملف القفل لتجاوز تنزيل مختلف أو ملف مفقود.
3. شغّل npm test، ثم فحوص الواجهة والتكامل المتعلقة بالتغيير. لا تستخدم ملف مستخدم متصفح شخصيًا.
4. شغّل npm run pack ثم npm run smoke:packaged-site-routes وnpm run smoke:packaged-browsers. شغّل npm run smoke:packaged-upgrade مع الاحتفاظ بحزمة 0.12 تحت dist/0.12.0 أو تحديد --old-root لاختبار المصدر. اختبار الترقية يحتاج حزمة سابقة محلية، ولا يُشغَّل تلقائيًا على CI الذي لا يملكها. تُجرى اختبارات النافذة من app.asar في Electron المطابق؛ هذا وحده لا يثبت تشغيل المثبت أو ترقية جهاز حقيقي.
5. شغّل npm run installer وnpm run verify:release. يفحص الأمر الأخير CRC والحجم وSHA-256 وتطابق ملفات المثبت والحزمة والمصدر والأدوات، دون تشغيل المثبت.
6. شغّل npm run source:archive. افحص manifest المصدر وبصمة الأرشيف، وأرفقه مع الإصدار. نسخة README داخل الأرشيف مخصصة للمستودع العام، ولا تحوي روابط إلى أدلة التطوير الخاصة.
7. أرفق نتائج اختبارات الترقية والمتصفحين والملف النهائي، وسجّل حالة توقيع المثبت. التوقيع غير مهيأ حاليًا.
   شغّل npm run smoke:auth-load -- مع مسار app.asar ثم مجلد الحزمة المطلق لاختبار المصادقة بالتزامن مع Chrome وEdge وبدء مساعد Windows ببطء متعمد. يتضمن smoke:packaged-upgrade مساري بيانات 0.12 و0.13؛ احتفظ بالحزمتين السابقتين. نفّذ كذلك [اختبار المثبّت داخل VM](VM-UPGRADE.md) وسجّل نتيجته مستقلة عن اختبارات البيانات.
8. قبل نشر الملفات التنفيذية للعامة، أكمل مصادر المكونات الخارجية المطابقة كما يوضح THIRD_PARTY_NOTICES.md، وفعّل قناة الإبلاغ الأمني في المستودع.

ملفات GitHub Actions تتحقق من المصدر عند الدفع وطلبات الدمج، وتتيح بناء حزمة يدويًا. لا تنشر إصدارًا تلقائيًا ولا ترفع بيانات مستخدم. لم تُشغّل هذه الملفات على GitHub في النسخة المحلية؛ نجاحها لا يُدّعى قبل ظهور تشغيل فعلي.

للبناء على قرص آخر يمكن ضبط SAHM_RELEASE_DIRECTORY وSAHM_PACK_DIRECTORY بمسارات مطلقة، وSAHM_SOURCE_DIRECTORY لمجلد تصدير المصدر. في 0.17 يضع التغليف ملفات العمل افتراضيًا تحت .build-temp في مجلد الإخراج، ويضع التحقق نسخته المؤقتة تحت .verify-temp هناك. ينقل المثبّت TEMP وTMP لعمليته فقط إلى مجلد البناء المختار. يمكن تغيير موضع العمل بـSAHM_BUILD_TEMP_DIRECTORY، وتغيير موضع استخراج التحقق بـSAHM_VERIFY_TEMPORARY_DIRECTORY. يُفحص القرصان قبل التغليف، وتُجمع المساحة المطلوبة إن كانا القرص نفسه. هذا تقدير احتياطي ولا يمنع برنامجًا آخر من استهلاك المساحة بعد الفحص. لا يزيل البناء تلقائيًا إصدارات سابقة أو بيانات مستخدم.

تُحفظ .npmrc مع أرشيف المصدر: omit=peer يستبعد أدوات Squirrel وmacOS غير المستخدمة في بناء NSIS. يستورد المثبّت واجهة app-builder-lib العامة مباشرة، ويستخدم التغليف والتحقق @electron/asar 4.3.1 المقفول. يتجاوز هذا الإصدار اعتماد ASAR 3 الذي طلبته بعض أدوات البناء؛ يغطي test/build-dependencies.test.mjs واجهات التدفقات والملفات المفكوكة وفحص الأرشيف المستخدمة. لا يوجد تجاوز لـglob إلى واجهة مختلفة داخل ASAR 3. تأتي 7-Zip من اعتماد 7zip-bin مستقل، دون تثبيت electron-winstaller أو تشغيل سكربته. راجع أي تغيير لهذه الاختيارات بالاختبارات والبناء الكامل.

لإعادة بناء مستقلة، صدّر المصدر وفكّه في مجلد جديد خارج شجرة التطوير. شغّل npm ci المعتاد مع .npmrc المرفقة، ثم npm run check وnpm audit. جهّز أدوات الفيديو من روابط ملف القفل، أو انسخ مخزنًا محليًا موثوقًا ثم شغّل npm run media:verify. شغّل npm test وnpm run pack وnpm run installer وnpm run verify:release من المصدر المستخرج نفسه، مع توجيه الإخراج إلى مجلد الإصدار الجديد. قارن SOURCE-MANIFEST.json والملفات الإنتاجية بالأرشيف المسلّم. سجل مصدر أدوات الفيديو وطريقة تجهيزها؛ لا تعني مطابقة الملفات الإنتاجية أن ملف NSIS سيُعاد إنتاجه بايتًا ببايت.

من 0.21، شغّل كذلك npm run test:protocol-stress على app.asar وSAHM.exe وأدوات الوسائط من الحزمة نفسها، لمدة 1800 ثانية في القبول الطويل. يجب أن تعود تنزيلات FTP وHLS وDASH دون أوامر استئناف بعد انقطاع الشبكة، وأن تتطابق بايتات FTP وبصمتا الصوت والصورة المفكوكان مع المرجع السليم. راجع موجات الإيقاف اليدوي وإعادة تشغيل التطبيق على حدة، واحتفظ بكل إخفاق. لا تُعد أخطاء الدخول والشهادات والقرص ورفض المصدر أسبابًا لإعادة محاولة عامة.
