# نشر إضافة سَهم والتثبيت من المتصفح

المسار المجاني المختار هو **Microsoft Edge Add-ons**. لا توجد رسوم لتسجيل ناشر إضافات Edge أو إرسالها، لكن يلزم حساب Microsoft وبيانات ناشر ومراجعة المتجر. افتح [لوحة الناشر](https://partner.microsoft.com/dashboard/microsoftedge/overview) وسجّل الدخول بنفسك. لا يكفي حفظ ZIP ليصبح التثبيت من المتجر متاحًا.

على Chrome في Windows، النشر العام دون وضع المطوّر يحتاج Chrome Web Store. تسجيل ناشره يتطلب رسمًا لمرة واحدة، ولا يحل متجر Edge محل متجر Chrome. إضافة Chrome الحالية تسهّل تنزيل YouTube، وهي ميزة تذكرها Google ضمن أسباب الرفض. يلزم حسم نطاق إصدار Chrome ومراجعة امتثاله قبل إرساله؛ لم تُخفَ هذه الميزة ولم تُحذف من المشروع.

## تجهيز طلب Edge

1. جهّز مستودعًا عامًا للمصدر تحت GPL-3.0-or-later وصفحة لتنزيل تطبيق Windows ووسيلة دعم فعلية. يمكن استخدام GitHub Releases وGitHub Pages ضمن الخطة المجانية. وجود الملفات محليًا لا يعني نشر هذه الصفحات.
2. انشر [سياسة الخصوصية العربية](EXTENSION-PRIVACY.md) و[الإنجليزية](extension-store/privacy.en.md) بعد إضافة اسم الناشر ووسيلة اتصال فعلية. لا تستخدم رابطًا وهميًا أو صفحة غير متاحة.
3. املأ browser/publisher.json: name وprivacyUrl وsupportUrl وhomepageUrl. هذه بيانات عامة؛ لا تضع كلمة مرور أو رمز API أو عنوانًا شخصيًا فيها.
4. شغّل npm run extension:status -- --require-submission. يبقى الفحص غير ناجح حتى تكتمل بيانات النشر. لا يتحقق هذا الفحص من إتاحة الصفحات على الإنترنت أو اعتماد المتجر.
5. شغّل npm run extension:package. يحتوي ZIP ملف manifest متعدد اللغات والأيقونات والكود؛ لا يحتوي مفتاح التطوير المثبت أو ملفات المستخدم أو التطبيق. بجانبه نصا الوصف بالعربية والإنجليزية وملاحظات المراجع والصلاحيات وحالة الجاهزية. حزمة الإصدار الحالي مرشحة لـEdge، وليست حزمة Chrome مقبولة.
6. ارفع ZIP إلى عنصر جديد في لوحة Edge. أدخل الوصف والصور الفعلية والخصوصية والصلاحيات ووسيلة الدعم. لا تُرسل طلبًا بمعلومات تجريبية. عرّف بوضوح اعتماد الإضافة على تطبيق Windows ووظائف الوسائط والجلسات وPOST.
7. بعد أن يخصص المتجر معرف الإضافة، جهّز **بناء اعتماد للمراجع** يثق بهذا المعرف حتى يستطيع اختبار Native Messaging. لا تفعّل رابط متجر للعامة قبل إتاحته: ملف browser/store-release.json في بناء المستخدم يحتوي فقط المعرف والرابط الفعليين لإضافة منشورة. يبقى المتجر الآخر null.
8. أعد بناء الحزمة واختبر من صفحة الإضافة الحقيقية في ملف متصفح جديد. يجب اختبار الموافقة والصلاحيات والاتصال وGET والجلسات وPOST والفيديو والتحديث والإزالة. الاختبار المحلي بواسطة تحميل إضافة غير مضغوطة يختبر الوظائف فقط ولا يثبت نجاح تثبيت المتجر.

## ربط الإصدار المنشور بالمثبّت

قيمة edge أو chrome في browser/store-release.json كائن من id وurl. يجب أن يتطابق المعرف مع آخر جزء من رابط HTTPS على microsoftedge.microsoft.com/addons/detail/ أو chromewebstore.google.com/detail/. تُرفض روابط التحويل والنطاقات المشابهة والمعرفات غير الصالحة. لا يُقبل معرف يرسله موقع أو مستخدم من واجهة التطبيق.

شغّل npm run extension:status -- --require=edge، ثم اضبط SAHM_REQUIRE_EXTENSION_STORES=edge عند تشغيل npm run pack. يمنع ذلك بناء حزمة توزيع يفترض أنها مرتبطة بـEdge بينما بيانات المتجر مفقودة. يمكن بناء نسخة تجريبية دون هذا المتغير؛ لا تصبح بذلك نسخة مثبتة من المتجر.

خيار إعداد المتصفح في المثبّت غير محدد افتراضيًا. عند موافقة المستخدم وتشغيل سَهم من صفحة الإنهاء، يعرض التطبيق المتصفحات المثبتة التي تتوفر لها إضافة منشورة. يمكن فتح المتجرين إذا توفرا. تُسجّل قناة الاتصال المحلية بعد اختيار متصفح متاح وقبل فتح صفحته، ولا تُسجّل إذا أُجّل الحوار أو غاب المتصفح. الموافقة النهائية على إضافة الامتداد تبقى داخل المتصفح. لا يكتب المثبّت سياسات مؤسسية ولا يفعّل وضع المطوّر.

جُهز مستودع عام وصفحتا الخصوصية والدعم على GitHub. لم يُقدّم حساب ناشر Edge جاهز ولم تُنشر الإضافة في المتجر. تبقى أزرار المتاجر معطلة، ويظهر الإعداد اليدوي للنسخة التجريبية مع حالة منفصلة لكل متصفح. لا يُستبدل رابط حقيقي بمعرف تجريبي لتجاوز هذه الخطوة.
