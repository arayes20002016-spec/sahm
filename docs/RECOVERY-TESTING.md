# التعافي واعتماد أدوات البناء

يستخدم سَهم 0.16 كتابة مؤقتة مع fsync قبل نشر نقطة الاستئناف. يبقى ملف الحالة السابق عند فشل الكتابة أو المزامنة أو إعادة التسمية. يتشارك سجل المهام والإعدادات معالجة أخطاء مشاركة الملفات المؤقتة في Windows، دون حذف آخر حالة صالحة لتجاوز الخطأ.

تُنهي اختبارات test/recovery.test.mjs عملية Node فرعية قسرًا أثناء نقل HTTP، ثم تعيد فتح سجل المهام وتستأنف الأجزاء إلى البايتات المتوقعة. وتُنهي عمليتين أخريين بعد إنشاء رابط الملف النهائي وقبل حذف الأجزاء، وبعد حذف الأجزاء وقبل حذف بيان الاستئناف. في الحالتين يتعرف الاسترجاع على معرف الملف في نظام الملفات ويكمل التنظيف دون طلب شبكة جديد. لا يكفي تطابق الاسم أو الحجم أو المحتوى للسماح بحذف جزء أو اعتماد ملف آخر.

تغطي الاختبارات أيضًا تغير ETag بعد الانقطاع، مع حفظ الأجزاء القديمة، ووجود ملف مستخدم في المسار النهائي دون استبداله. تحاكي اختبارات checkpoint فشل ENOSPC في الكتابة وfsync ثم نجاح الحفظ بعد زوال العطل. هذا حقن خطأ عند واجهة الملفات؛ لا يثبت سلوك قرص مادي ممتلئ أو انقطاع طاقة فعلي. لا يضمن fsync وحده حفظ عتاد تخزين يتجاهل طلبات التفريغ، ولا ندّعي اختبار جميع أنظمة الملفات أو مسارات الشبكة.

كان تدقيق npm في 0.15 يسجل ثمانية إدخالات تتبع سلسلة global-agent 3 وroarr وsprintf-js. لا يورد [التنبيه الأصلي إصدارًا مصححًا لـsprintf-js](https://github.com/advisories/GHSA-hp3w-g68c-fv3c). يستخدم 0.16 تجاوزًا محدودًا لاعتماد global-agent داخل @electron/get إلى الإصدار 4.1.3، الذي يزيل هذه السلسلة. يحفظ package-lock.json الإصدارات وبصمات npm. يتحقق test/build-dependencies.test.mjs من واجهة bootstrap وتنزيل أداة البناء عبر وكيل HTTP محلي واستثناء NO_PROXY ورفض بصمة خاطئة. لا يغيّر هذا اعتماد وكيل التنزيل الخاص بالمستخدم.

يفحص CI اعتماد npm الكامل عند درجة moderate وما فوق. نتيجة npm audit تخص قاعدة التنبيهات وقت الفحص واعتماد npm؛ لا تثبت خلو Electron أو أدوات الفيديو أو جميع المكونات الخارجية من العيوب.

يفصل 0.17 أدوات NSIS عن Squirrel، ويستخدم ASAR 4.3.1 مع اختبارات لواجهات التدفقات والملفات المفكوكة والتحقق التي يستعملها البناء. لم يُستبدل glob داخل ASAR 3 بواجهة غير متوافقة. تتضمن حزمة المصدر .npmrc لاستبعاد أدوات peer غير المستخدمة، وتستخدم أدوات التحقق والنشر اعتماد 7-Zip مستقلًا. توثّق سجلات npm ci الفعلية غياب تحذيرات التقادم، ولا يُعتمد غياب النص وحده دون اكتمال التغليف وبناء المثبّت وفحصه.

تفحص اختبارات test/build-storage.test.mjs جمع احتياطي الإخراج والعمل المؤقت على القرص نفسه، ونفاد المساحة على قرص مؤقت منفصل، وتراجع المساحة بين قراءتين، وقبول احتياطيات منفصلة كافية. اختيار مجلد العمل قرب الإخراج يجنّب الاعتماد على مساحة C المحدودة افتراضيًا. يبقى هذا الفحص تقديرًا قبل البناء، وقد يستهلك برنامج آخر المساحة لاحقًا.

توجد أدوات إلغاء المثبّت والتعافي منه في scripts/vm/guest-cancel.ps1. لا تعمل إلا في الضيف المملوك الموسوم وبحساب SAHMTest القياسي. تشمل إلغاء معالج تثبيت جديد وإلغاء الترقية قبل نسخ الملفات، مع فحص الملفات والتسجيلات وبقاء النسخة السابقة عاملة. وتشمل إنهاء عمليات المثبّت أثناء فك ملفات تثبيت جديد، ثم إعادة تشغيل المثبّت والتحقق من نسخة التطبيق وبصمته. لا يعني نجاح هذا المسار وجود تراجع تلقائي عن ترقية قُطعت أثناء الكتابة؛ تبقى تلك حالة قبول مستقلة.
